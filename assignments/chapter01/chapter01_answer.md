# 4. 잘못된 데이터가 결과를 바꾸는 과정

## 4-1. 주문 데이터 확인

다음 데이터를 입력한 뒤 실제 결과를 확인합니다.

## 4-2. 실행 전 예상

업무적으로 주문이 `ORD-001`, `ORD-002` 두 건이고 `order_code`가 주문을 고유하게 구분한다고 **가정할 경우** 예상 합계: 30000

```text
__500000__ 원
```

## 4-3. SQL 합계

```sql

```

실제 결과:

```text

## 4-4. 결과 해석

### `SUM` 문법 자체가 잘못된 것인가요?

```문법 자체가 틀린 것은 아니다. 

```AI 답안 : 컴퓨터는 입력된 코드를 그대로 정확하게 계산했을 뿐입니다. 문제는 문법이 아니라 더하려는 대상 데이터(테이블 구조)에 있습니다.

### 결과 차이의 원인은 무엇인가요?

``` ORD-002라는 주문번호가 중복된건지, 아니면 같은 주문번호에 두 개의 상세 상품이 엮여 있는지 알 수 없어 차이가 있다. 

```AI 답안 : ORD-002 데이터가 여러 행으로 펼쳐져 있는 상태(예: 하나의 주문에 여러 상세 상품이 조인되어 행이 늘어난 상태)에서 그대로 SUM을 수행했기 때문에, 동일한 주문 금액이 중복으로 합산되어 총액이 실제보다 부풀려졌습니다.

### SQL이 정확하게 실행되어도 업무 숫자가 잘못될 수 있는 이유를 설명하세요.

```주문 번호 중복 같은 규칙이 정해져 있지 않아 실제 결과와 차이가 있을 수 있다.

```AI 답안 : 컴퓨터는 데이터의 '비즈니스적 의미'를 이해하지 못하고 오직 주어진 코드와 행(Row) 단위로만 계산하기 때문입니다. 데이터 구조(1:N 관계 등)를 고려하지 않은 채 무작정 집계 함수를 쓰면, 문법 에러 없이 완벽하게 실행되더라도 실제 비즈니스 지표(매출, 통계 등)는 완전히 왜곡될 수 있습니다.

# 5. 파일·스프레드시트·DBMS 선택 연습

각 사례에 대해 **AI에게 묻기 전에 먼저 본인의 판단을 작성**합니다.

## 사례 A. 개인 독서 기록

```text
나의 선택: 파일
선택 이유: 한사람이 사용하고, 복잡한 관계나 권한이 필요 없으므로
어떤 조건이 추가되면 다른 방식으로 바꿀 것인지: 여러 사람이 사용하고, 데이터의 관계나 권한이 필요해진다면 DBMS를 고려해볼 수 있을 것 같다. 
```

## 사례 B. 동아리 행사 신청 명단

```text

나의 선택: 스프레드시트
선택 이유: 혼자 쓰는 것이 아니고, 공동 편집이 가능하지만, 너무 복잡한 업무에는 사용 불가능하다. 
어떤 조건이 추가되면 다른 방식으로 바꿀 것인지: 더 많은 권한과 인원이 사용하게된다면 다른 조건
```

## 사례 C. 온라인 강의 서비스

```text

나의 선택: DBMS
선택 이유: 권한과 복구가 중요하고, 여러 사람들이 서로 연결된 작업을 하기 때문에
어떤 조건이 추가되면 다른 방식으로 바꿀 것인지: 보다 간단한 업무와 소규모의 사람들이 접근하는 서비스라면 스프레드시트를 고려해볼 수 있다.
